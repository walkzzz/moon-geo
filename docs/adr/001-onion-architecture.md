# ADR-001：九层洋葱架构与单向依赖

**状态**：已接受  
**日期**：2026-01  
**决策者**：项目创始人  

## 背景

统一空间数学引擎需要覆盖从基础数值到业务对接的全栈能力。需确定分层策略，确保内层稳定、外层灵活，且依赖关系清晰可维护。

## 决策

采用九层洋葱型分层架构：

| 层 | 包名 | 职责 |
|----|------|------|
| -1 | util | 数域/数值/矩阵/精度体系 |
| 0 | atop | 拓扑空间/流形/范畴化抽象 |
| 1 | space | 欧氏/复/射影/非欧/时空/栅格 |
| 2 | alg | 代数簇/变换/不变量/求交 |
| 3 | bv | 全类型包围体/空间索引树 |
| 4 | brep | 流形/非流形/胞腔复形/奇异拓扑 |
| 5 | algo | 基础几何/GIS/高阶拓扑/优化 |
| 6 | parallel | CPU多线程/GPU/分布式 |
| 7 | domain | CAD/GIS/仿真/视觉/机器人 |
| 8 | eco | 语言绑定/格式兼容/引擎对接 |

**依赖铁律**：上层只能依赖下层，禁止反向依赖和同层环依赖。

## 理由

- **洋葱型**：内层更稳定抽象（数学不变），外层更灵活业务（需求变化），符合"稳定向内、变化向外"原则
- **九层**：对标 CGAL（内核→几何内核→几何结构→算法）但更细粒度，将拓扑/包围体/并行分离
- **单向依赖**：避免环依赖导致的编译/测试/重构困难，20 年项目必须

## 否决的方案

1. **扁平架构**：所有类型放一个包——无法管理依赖，重构困难
2. **微服务架构**：每层独立服务——几何计算是高频低延迟调用，网络开销不可接受
3. **更少层数（5层）**：bv/brep/parallel 分离是性能和可维护性的关键，合并会导致"上帝包"

## 影响

- 新增功能必须确定所属层，且只依赖下层
- 跨层调用需经评审
- 外部依赖引入需评审（防止隐式反向依赖）
